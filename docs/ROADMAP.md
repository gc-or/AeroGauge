# 下一步与协作

## 两人分工

1. 飞行底座：接真实悬停 actor；核对离线观测/动作；标定推力、延迟；扩展起飞/降落模式。
2. 评估系统：制定任务特有通过门槛；添加速度阶跃/八字；单因素参数扫描和失败分析；之后做观测退化与多随机种子统计。
3. 共同：统一公共接口和标称配置；将参数标定与鲁棒性范围分开；确定开发集与最终保留集。

先完成基础飞行与硬件参数不确定性；复杂风和运动平台作为可独立增加的专项场景。首版没有加入海洋引擎、服务器、数据库或前端。

## GitHub 起步

- 以 AeroGauge 目录作为独立仓库根，运行必需资产使用包内相对路径。
- 首次提交前检查忽略规则，避免包含原参考压缩包、虚拟环境、缓存、训练权重及大批量输出。
- `main` 保持可运行；按任务建短分支，例如 `feat/takeoff-landing`、`feat/parameter-sweep`、`feat/observation-noise`。
- 一个 PR 处理一项能力，说明输入/输出变化、测试命令及结果。公共接口两人确认。
- 已提供 Ubuntu/Python 3.11 的 CI 定义；远端创建前未实际运行 GitHub Actions，不声称 Ubuntu 已验证。
- 已获用户授权，仓库目标为公开的 `gc-or/AeroGauge`；邀请同伴及日常分支操作见 `CONTRIBUTING.md`。
