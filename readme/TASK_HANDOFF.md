# AeroGauge 跨电脑任务承接说明

整理日期：2026-10-29。供项目成员与另一台电脑上的编码助手使用。此文件概括本次对话已确定的需求，不替代运行日志；实际版本、仓库与测试状态请结合 Git 和输出 manifest 检查。

## 1. 项目目标和范围

项目名 AeroGauge，首个对象是课题组现有 WRJ 四旋翼。参考 RoboGauge（https://github.com/wty-yy/RoboGauge）的任务分层、多个随机种子、条件扫描、指标聚合和能力边界评估方式，建立面向无人机的通用评估平台。

重点是基础飞行、动态跟踪、硬件与模型参数偏差、观测与执行退化、外部扰动。风、浪、海上运动平台降落是后续专项环境，不能将整个工程缩减为海上降落项目。先建立可信的通用飞行底座，再增加场景。

评估不等于重新训练：加载训练好的策略，在统一条件下闭环运行、记录成功和失败、分析指标。不同控制层级的策略分别评估，不能将速度规划器和直接电机控制策略放在不明接口下直接比较。

## 2. 已明确的需求

| 测试组 | 任务/条件 | 主要结果 |
|---|---|---|
| 基础飞行 | 起飞、悬停、定点、降落 | 稳态误差、漂移、触地速度 |
| 动态跟踪 | 位置阶跃、速度切换、圆形、八字 | 超调、响应时间、轨迹误差 |
| 扰动恢复 | 外力脉冲、持续扰动、阵风 | 最大偏离、恢复时间、失稳情况 |
| 参数偏差 | 载荷、重心、惯量、推力系数等 | 对模型失配的敏感程度 |
| 观测和执行退化 | 噪声、偏置、延迟、丢帧、电机滞后 | 容忍范围、闭环稳定性 |
| 后续自主/专项任务 | 障碍、目标降落、随浪运动的平台 | 成功率、碰撞、耗时与接触质量 |

用户当前希望两人开发，先上传一个框架，再通过 Git 持续完善组件。当前电脑用于开发和整理，**不是部署/训练环境**；不要由本机检查结果推定部署电脑已安装或运行通过。

## 3. 两人分工

- 飞行底座负责人：无人机资产、动力学、电机/执行器、基线控制器、模型观测与动作适配、参数标定。主要维护 vehicle.py、simulation.py、policies.py。
- 评估负责人：任务指令、初始条件、测试组合、指标、成功/失败定义、重复运行和报告。主要维护 tasks.py、evaluation.py 和 configs/。
- 公共接口共同确认，尤其坐标系、电机顺序、单位、控制频率和观测/动作语义。
- 底座方实现可调机制，评估方通过配置组织扫描，避免各自重写机体模型。先单因素，再小规模组合。

## 4. 训练与评估环境

用户的主训练环境：Isaac Sim 5.1.0.0 + Isaac Lab 2.3.2 + PyTorch 2.7.0 + cu128。参考压缩包记录实际 Lab 分发为 2.3.2.post1，与 v2.3.2 参考源码 tag 要区分。当前未再次登录部署机核验。

首版评估后端固定 MuJoCo 3.15.0。理由是现有资产和参考项目资产检查曾用该版本，本项目也已运行验证。2026-10-29 查到官方稳定版为 3.17.0；更新引擎可能影响求解器、接触、API 和可重复性，所以先固定基线，之后独立环境做版本对照。不要直接更新用户已有 Isaac 训练环境。

推荐部署评估端独立 Python 3.11 环境；项目声明支持 Python 3.11–3.12。开发机本轮实测 Windows / Python 3.12.15 / MuJoCo 3.15.0。普通 MuJoCo 仿真不依赖 CUDA 或 PyTorch；模型推理是可选依赖，首次真实迁移优先与训练导出版本对齐。

Isaac→MuJoCo 是 Sim-to-Sim。能加载文件不代表观测、执行器、接触和动力学一致。先离线比较同一状态下的观测/动作，再短时比较轨迹。

## 5. 现有资产与物理约定

运行资产已放在 `aerogauge/data/wrj/`，无需原电脑的大目录。原项目源资产在大目录 `models/simulation/wrj_sim_v1/`，本轮没有修改；只复制 MuJoCo 运行所需子集，67 个来源文件校验值见 `aerogauge/data/provenance.json`。

- 一个自由刚体，约 0.797048708 kg，完整惯量张量，72 个显示实例、36 个碰撞实例。
- 世界 W 右手、Z 向上；控制 B 为 FLU。资产 S 的机头是 −X，R_BS=diag(-1,-1,+1)，原点为原标定重心。
- 新电机 1/2/3/4 为前左/前右/后左/后右，对应旧 motor_3/motor_1/motor_4/motor_2。
- 仿真反扭矩符号 [+,−,−,+]，κ=0.016 m；T5147-3 曲线代理目标 T5146，单电机参考边界约 15.473913 N。
- 不对称配平推力约 [1.984307,1.961344,1.948180,1.925217] N；不能简单等分 mg/4。
- 部分质量、动力和接触参数仍是估算/代理；不将其称为实机辨识结果或已验证数字孪生。
- 合力/合矩在实际 COM 施加一次，不重复添加电机力臂矩。

`.gitattributes` 保持资产和配置快照原始字节，避免 Git 换行转换使来源哈希失效。修改参数使用外部配置，不覆盖原始资产冒充标定。

## 6. 当前已经实现

入口为 `python -m aerogauge`，项目说明见根 README.md。

- 基线位置/姿态 PD 控制器；默认从离地 1 m 开始。
- 悬停、0.5 m 位置阶跃、圆形位置/速度参考。
- 质量/惯量比例、重心偏移、分电机推力偏差、κ、电机一阶滞后、延迟。
- 恒定外力、脉冲、简化相对风速机体二次阻力。
- 固定种子初态、完整配置、代码和资产哈希、每回合 CSV、失败原因和汇总 JSON。
- 无状态 TorchScript hover16 actor 接入，不直接读取原 RSL-RL checkpoint。
- 基础 CI 和协作指南 CONTRIBUTING.md。

默认 2 ms 物理步、20 ms 控制周期、10 s 回合。初态分布是 AeroGauge 简化定义，不是已经复现参考包原固定评估集。

当前成功门槛是完整运行且最后 2 s 每个控制采样点同时满足：位置误差 <0.1 m、速度误差 <0.1 m/s、倾角 <10°、角速度 <0.3 rad/s，并且无地面接触或越限。阶跃暂态仍需结合整段指标，不能只看末段通过率。提前失败保留轨迹、终止原因、时长，计入分母。

## 7. 参考包与策略接口

参考输入为 wrj_landing_review_20261028.tar.gz，包名和 SHA256 在 provenance.json 中。它包含 Isaac 训练、悬停、速度/降落及多轮实验快照。未将整个压缩包、训练依赖、权重和输出上传。

1. 悬停：16 维，机体系目标位置误差3、线速度3、角速度3、投影重力3、上一动作4。每项尺度按对应模型保存配置核对。
2. 悬停动作：四路配平推力修正，f=trim×(1+0.5×clip(a,−1,1))；不是满量程油门。
3. 降落案例：44 维观测，输出 heading FLU 下绝对地速与偏航角速度，并依赖底层控制器和接触/积分状态；当前未移植，不能直接接四电机执行端。
4. TorchScript 当前要求 float32 (batch,16)→(batch,4)，无状态单张量输出。归一化如存在，封装在导出模块内；循环策略需要另写隐状态适配器。

详细分析见 docs/REFERENCE_REVIEW.md；配置快照在 docs/reference_snapshot/；公共接口见 docs/INTERFACES.md。

- 12 个基础测试通过，包括配平、完整惯量下单电机力矩、自由飞行、重置、参数变化、延迟、风力方向、成功/失败记录等。
- 3 个种子标称悬停通过，平均位置 RMSE 约 0.03197 m。阶跃/圆形各一个种子完成测试。
- 质量增加 10%、控制器保持原标称参数时未达末段误差门槛，结果被记录而非自动重新整定。
- 电机滞后/延迟、外力脉冲、简化风演示已实际运行。
- 两个合成 TorchScript 接口测试在另一套本地 Python 3.13 / PyTorch 2.6.0 CPU 环境通过；这不等于 PyTorch 2.7 真权重验证。
- 安装入口、依赖检查和离屏渲染通过。详细记录 docs/VALIDATION.md。

## 9. 下一步建议

1. 在部署电脑克隆项目，独立环境安装，先运行基础测试与悬停命令，记录平台和依赖。
2. 选择一个明确契约的悬停权重，从训练环境导出确定性 actor，核对观测和动作；不要按文件扩展名自动猜模型结构。
3. 补充基础起飞/降落与任务特有指标，同时组织质量、电机、延迟等单因素扫描。
4. 建立开发集与保留集；区分按数据标定物理参数和在参数范围内评估鲁棒性。正式比较时冻结模型和协议。
5. 再加入传感器退化、阵风和专项场景。风速需要受力模型，外力 N 与风速 m/s 不混用；机体风阻不是旋翼气动或船体尾流。
6. 海上专项确实需要时，先规定平台六自由度运动或回放实测船体运动。平台幅度不是波高，波浪到船响应需单独建模；移动甲板的接触速度必须正确。
