## 2. 机头方向与坐标转换

将现有包的刚体坐标记为 **S**，控制器使用的 FLU 机体系记为 **B**。两者原点相同，都在标定重心；只改变分量的表达方式。

机头为 −X_S 的核对依据：

- 相机实例 `depth_camera_d435i_01` 的局部 +Z 面朝方向经实例旋转后为 `[-1,0,0]`（数值误差约 1e−14）。结合用户指定的相机正面，它指向 −X_S。
- 相机质心 X_S 约 −38.15 mm，支撑背板质心 X_S 约 −23.98 mm；相机处于背板的 −X 一侧。
- 两根 150 mm 落地管的局部长度轴变换后，分别约为 `[-0.999989,-0.004102,-0.002368]`、`[-0.999994,+0.003024,-0.001746]`，即沿 ±X_S 前后布置。保留模型中微小装配偏差，不用它们重新定义倾斜的控制坐标系。

因此约定：

```text
x_B = −X_S    前
y_B = −Y_S    左
z_B = +Z_S    上

R_BS = diag(−1, −1, +1)
p_B = R_BS p_S
v_B = R_BS v_S
ω_body,B = R_BS ω_body,S
I_B = R_BS I_S R_BSᵀ
```

这里 `R_BS` 表示把 S 分量转换成 B 分量，是绕 z 轴 180° 的旋转，行列式为 +1，**不是镜像**。旋翼转速下文用 Ω，避免与机体角速度 ω_body 混淆。

现有资产的根刚体仍使用 S。若仿真给出根刚体姿态 `R_WS`，控制姿态为 `R_WB = R_WS R_SB`，其中 `R_SB = R_BSᵀ`。控制器算出的合力/合矩应转换回 S 或世界系，再交给引擎。不要只改电机坐标，却漏改姿态误差、角速度、力矩和惯量。

默认资产姿态若为 `R_WS = I`，机头在世界 −X；若场景希望机头初始朝世界 +X，可在部署场景的生成位姿中设置绕 z 轴 180°，无需修改网格。**实际改变生成姿态和读取机体姿态时的坐标转换是不同步骤，不要重复旋转模型。**

变换后的完整惯量张量（kg·m²）为：

```text
I_B = [[ 3.138019260155e−3, −2.402647076784e−7, −5.988083578839e−5],
       [−2.402647076784e−7,  3.174722737730e−3, −2.226766062063e−5],
       [−5.988083578839e−5, −2.226766062063e−5,  3.984052536793e−3]]
```

保留这些非对角项。USD 的惯量主轴表示不等于机头坐标；不要把主惯量三个数直接当作 FLU 下的对角惯量。

若后续对接使用 FRD（前、右、下）的控制器，还需 `R_FRD,B = diag(1,−1,−1)`；FLU 下向上推力为 +z，FRD 下则为 −z。相机光学坐标、像素轴和传感器内参仍需单独配置，不能由“机头已确认”推断全部完成。

### 4.1 推力模型：优先查表，其次使用局部平方律

采用 Ω 为机械角速度、单位 rad/s，推力 f 单位 N：

```text
Ω = RPM × 2π / 60
f = k_f Ω²
k_f 单位 = N / (rad/s)²
```

五点过原点最小二乘：令 `z_j = Ω_j²`，则 `k_f = Σ(z_j f_j) / Σ(z_j²)`。

| 参考桨 | 五点拟合 k_f | 最大测试推力 N | 最大测试 RPM | 20% 点的推力拟合相对误差 |
| --- | ---: | ---: | ---: | ---: |
| P49436-3 | 1.220332331e−6 | 13.269378115 | 31486.2 | +7.92% |
| T5143S-3 | 1.232603663e−6 | 13.305662720 | 31362.7 | +10.36% |
| **T5147-3** | **1.595069526e−6** | **15.473913035** | **29715.1** | **+10.35%** |

全量拟合更偏重大推力点；本机悬停接近第一个测试点，不能忽略上述误差。建议默认在 `(Ω², f)` 五个节点间分段线性插值，并用相同曲线反解目标转速。这样测试区间内恰好经过原数据点，又避免高阶拟合振荡。

测试数据不覆盖 0–20% 油门：若初版仿真需要连续模型，可添加人工 `(Ω²=0,f=0)` 节点连接到首个测试点，**这一段是外推假设**，不能代表真实解锁转速、死区或怠速推力。大于最大节点不外推；最大节点也只是参考桨的测试边界，不是实机持续飞行额定值。

当前平均悬停推力为 `mg/4 = 1.954761956672 N`，位于 T5147 前两点之间。按上述曲线反解：

- 平均参考转速约 **11070.85 RPM**。
- 在该工作点取 `k_f,hover = f_hover / Ω_hover² = 1.454368967e−6 N/(rad/s)²`。
- 若控制接口只能用一个常数，悬停小扰动仿真可暂用该局部值；它只锚定该工作点，**不是全域最小二乘系数，也不是曲线导数**。

推荐查表模型和局部平方律是两个实现选项，不能同时叠加。使用局部系数时，不要再把 15.4739 N 和 29715.1 RPM 当作同时满足该局部平方律的端点。

测试电压约 23.5–24.0 V；6S 并不意味着任何时刻都为 24 V。测试表中的油门百分比依赖台架电调设置，不等于 Isaac 的归一化力指令或真实 PWM/DShot 标定。初版先以 **N / rad/s** 为控制接口；低电压、电池压降、真实 ESC 映射后续补充。四路参考峰值推重比约 7.92，只表示此代理数据与当前模型质量的比值，不等于已验证整机性能。

## 5. 反扭矩：能估算，但不能从电功率直接辨识

定义 `Q ≥ 0` 为稳态空气阻力矩幅值，`κ = Q/f`（单位 m），机体偏航力矩为 `s_i Q_i`。用户测试表没有测量 Q，推力、RPM 和电功率三列也不能唯一决定它。

在静态台架、稳态、无外部能量输入条件下：

```text
Q = P_aero / Ω
P_aero = η_eff P_elec
Q = η_eff P_elec / Ω
0 ≤ η_eff ≤ 1
```

η_eff 为电功率到旋翼空气阻力功率的有效比例，包含电机/相关电气与机械损耗的影响。`P_elec/Ω` 只能作该条件下的能量上界；不能直接当作真实 Q。也不以 KV 常数乘测试表的直流输入电流，冒充已测轴扭矩。

为了让部署端先跑通偏航控制，**人为假设 η_eff = 0.70**，不是厂家给定效率。平均悬停点按推力在相邻节点间插值得到 `P_elec ≈ 51.2450 W`、`Ω ≈ 1159.337 rad/s`，从而 `κ ≈ 0.01583 m`。取便于使用的 **κ₀ = 0.016 m** 作为悬停初值。

如果仅将 η_eff 改为 0.60–0.80，同一点会得到 κ 约 0.01357–0.01809 m；这是**假设敏感性范围，不是实测置信区间，也不包括所有桨型误差**。可以先按这三个效率场景比较偏航响应，再用真实扭矩数据替换。

| T5147 测试油门 | P_elec/Ω，稳态能量上界 Nm | 假设 η_eff=0.70 的 Q，Nm | 同假设下 κ，m |
| --- | ---: | ---: | ---: |
| 20% | 0.041461 | 0.029023 | 0.015894 |
| 40% | 0.084924 | 0.059446 | 0.012851 |
| 60% | 0.132283 | 0.092598 | 0.012649 |
| 80% | 0.187821 | 0.131475 | 0.011707 |
| 100% | 0.263742 | 0.184619 | 0.011931 |

这也说明常数 κ₀=0.016 只适合作为悬停附近的简单起点。若扩展到全油门域，可基于同一 η_eff 假设构建 Q 查表，与推力查表共同使用；这仍是估算，且分配器的偏航项要随工作点更新，不能继续声称使用完全相同的常数 κ。

若接口采用 `Q = k_q Ω²`，悬停局部模型对应：

```text
k_f,hover = 1.454368967e−6  N/(rad/s)²
κ₀        = 0.016          m
k_q,hover = κ₀ k_f,hover = 2.326990347e−8  Nm/(rad/s)²
τ_yaw,i   = s_i k_q,hover Ω_i²
```

这些带单位系数不是无量纲 C_T / C_Q；转速如使用 rev/s 或 RPM，系数必须换算，不能直接复用数值。电机时间常数、电调延迟、旋翼自转惯量和加速反扭矩均未由稳态数据识别。若第一轮采用瞬时推力响应，应明确标记为理想执行器；不能据此声称已验证真实动态或可直接训练迁移实机。

## 6. 使用实际力臂的推力分配

在 B 系，四个旋翼平行向上，`f = [f₁,f₂,f₃,f₄]ᵀ` 为非负推力，`r_i = [x_i,y_i,z_i]ᵀ` 为上表位置。

```text
F_i = [0,0,f_i]ᵀ
r_i × F_i = [y_i f_i, −x_i f_i, 0]ᵀ

w = [F_z, τ_x, τ_y, τ_z]ᵀ = A f

A[:,i] = [1, y_i, −x_i, s_i κ_i]ᵀ
```

四个 z_i 略不相同，但对于纯竖直推力，不参与滚转/俯仰力臂。若以后模型有倾斜推力轴，要用完整 `r_i × (f_i a_i)`，不能沿用这个简化矩阵。

共同 κ₀=0.016 m 时，新编号顺序的数值矩阵为：

```text
A = [[ 1,               1,               1,               1             ],
     [ 0.091792816627, −0.092854813030,  0.091792816627, −0.092900617549],
     [−0.091504886845, −0.091458869405,  0.093188547330,  0.093188547330],
     [ 0.016,          −0.016,          −0.016,           0.016         ]]
```

F_z 单位 N，后三项 Nm；后三行系数具有 m 单位。设重力加速度沿用已有 MuJoCo 场景的 `g=9.81 m/s²`。注意它与克力换算用的标准重力 9.80665 不同。

水平无接触、无外扰悬停：`w_hover = [7.819047826690,0,0,0]ᵀ`，求解 `A f_hover = w_hover`。

| 1 前左 | 1.984307411 | 202.3430 | 25.3779% | 11146.97 |
| 2 前右 | 1.961344300 | 200.0015 | 25.0842% | 11087.86 |
| 3 后左 | 1.948179613 | 198.6590 | 24.9158% | 11053.82 |

```text
τ_z = 0（共同 κ、上述交替旋向假设下）
```

所以使用精确分配不是为了改模型对称性，而是使现有不对称几何在静态下合矩为零。共同 κ 的具体数值会影响偏航控制增益，但不影响上述零偏航悬停解；若各电机 κ_i 不同或采用非线性 Q(f)，则要重新求解。

控制时先由位置/姿态控制器得到目标合力与力矩，再用 A 分配，而不是给四路固定加同一个悬停基值。可写为 `f = f_hover + solve(A, Δw)`，与直接求解 `solve(A,w)` 等价。超出可行推力范围时采用有界分配/去饱和，明确力矩优先级；**不能简单裁剪四个逆解分量后还认为原合力矩得到满足**。水平飞行姿态大幅变化时，总推力也不再固定等于 mg。

### 6.1 部署端可复算的小段代码

从 `wrj_sim_v1` 包根目录运行。仅依赖 NumPy，读取现有配置，不写入任何文件；示例输出只是分配检查，不构成飞行控制器。

```python
import json
from pathlib import Path
import numpy as np

v = json.loads(Path("config/vehicle.json").read_text(encoding="utf-8"))
by_name = {m["name"]: m for m in v["motors"]}
order = ["motor_3", "motor_1", "motor_4", "motor_2"]
R_BS = np.diag([-1.0, -1.0, 1.0])
positions_B = np.array([by_name[n]["position_m"] for n in order]) @ R_BS.T
axes_B = np.array([by_name[n]["thrust_axis"] for n in order]) @ R_BS.T
assert np.allclose(axes_B, [0, 0, 1], atol=1e-10)
signs = np.array([1.0, -1.0, -1.0, 1.0])  # body reaction torque, FLU
kappa = 0.016  # provisional, NOT measured
A = np.vstack((np.ones(4), positions_B[:, 1], -positions_B[:, 0], signs*kappa))
w_hover = np.array([v["mass_kg"] * 9.81, 0.0, 0.0, 0.0])
f_hover = np.linalg.solve(A, w_hover)
assert np.all(f_hover > 0)
assert np.allclose(A @ f_hover, w_hover, atol=1e-12, rtol=0)

# T5147 proxy: interpolation in squared mechanical speed, not throttle.
rpm = np.array([10732.8, 16597.0, 20537.6, 25207.7, 29715.1])
thrust = np.array([186.2, 471.7, 746.5, 1145.2, 1577.9]) * 0.00980665
omega_sq = (rpm * 2*np.pi / 60)**2
assert np.all((f_hover >= thrust[0]) & (f_hover <= thrust[-1]))
rpm_hover = np.sqrt(np.interp(f_hover, thrust, omega_sq)) * 60 / (2*np.pi)
inertia_B = R_BS @ np.array(v["inertia_com_kg_m2"]) @ R_BS.T
old_order = [m["name"] for m in v["motors"]]
f_old = np.array([f_hover[order.index(n)] for n in old_order])
print("new order:", order)
print("hover N:", f_hover)
print("proxy hover RPM:", rpm_hover)
print("old order:", old_order, "hover N:", f_old)
print("equal-thrust wrench:", A @ np.full(4, w_hover[0]/4))
print("residual:", A @ f_hover - w_hover)
print("inertia in FLU:", inertia_B)
```

## 7. Isaac / MuJoCo 接入与验证顺序

保留现有单刚体资产；四个旋翼是四个力的作用位置，不必为首轮控制测试拆成四个转动刚体。每个物理步用实际执行器推力计算合力/合矩，可选择以下一种方式：

- **逐点施力**：在各实际位置施加向上推力，另外施加反扭矩；引擎已由力作用点计算力臂矩，不再重复添加 `r×F`。
- **重心合力/合矩**：在重心施加 `F_B=[0,0,Σf_i]` 和 `τ_B=Σ(r_i×F_i + s_i κ_i f_i e_z)`，再转换到引擎 API 所要求的坐标系。不要同时再施加四路位置力。

若 API 使用现有根刚体局部坐标，输入 `F_S=R_SB F_B`、`τ_S=R_SB τ_B`；若使用世界坐标，输入 `F_W=R_WS R_SB F_B`、`τ_W=R_WS R_SB τ_B`。根刚体与重心在本资产中重合；以当前安装版本确认外力 API 的作用点和坐标选项，避免沿用其他版本的默认值。[Isaac Lab 官方刚体教程](https://isaac-sim.github.io/IsaacLab/main/source/tutorials/01_assets/run_rigid_object.html)可作为资产接入参考。

建议部署端按以下顺序记录结果：

1. 在俯视图标出机头及新编号，确认相机在 +x_B 一侧、新旧索引无误。记录 Isaac Sim / Isaac Lab 版本。
2. 做单路小推力的**合矩符号**测试：1 号应产生 `(+τ_x,−τ_y,+τ_z)`，2 号 `(-,−,−)`，3 号 `(+,+,−)`，4 号 `(-,+,+)`。惯量有非对角项，角加速度不必严格与力矩各分量一一独立；可用 `I_B⁻¹ τ_B` 核对零初始角速度时的响应。
3. 离地、水平、零初始速度且关闭外扰，施加本文件的 f_hover。先验算合力抵消重力、合矩接近零，再检查短时姿态漂移；不要把地面接触支撑误认为推力平衡。
4. 分别做小幅滚转、俯仰和偏航命令，检查正负方向和通道串扰，再测试限幅后的可实现合矩。
5. 分开记录“理想执行器”和后续加入延迟/时间常数的结果。检查改变质量、重心、κ 或参考桨曲线后，控制器是否重新计算平衡点。
6. 待上述通过，再接任务观测、动作缩放与 RL；训练记录中注明 T5147 代理、κ 假设、零至首点外推及尚未标定的执行器动态。当前不是已验证的 T5146 真机数字孪生。

现有碰撞/减震模型、部分小件质量和未计入摄像头线的状态不变。后续补质量后，整机重心、惯量、电机相对重心的位置与上述悬停分配都应重算；本表的小数精度只代表数值复算精度，不代表实物称重精度。
